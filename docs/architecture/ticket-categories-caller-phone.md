# Категории обращений и телефон звонящего

Ревизия `0015_ticket_categories` добавляет управляемый справочник тем без изменения типов заявок и существующего workflow.

## Справочник

Восемь начальных тем заданы в миграции. Имена уникальны без учёта регистра. Администратор с `users.manage` может добавлять, переименовывать, упорядочивать и отключать темы. Удаление не предусмотрено. Изменение требует CSRF, корректный Origin и актуальную версию `If-Match`; действие аудируется без персональных данных заявки. Оператор и инженер с `tickets.create` читают только активные темы. Для темы «Другое» backend требует уточнение `subject`.

При создании заявки сохраняются FK `category_id` и исходное `category_name`. Переименование и отключение справочника не переписывают старые заявки. Старые заявки сохраняют `NULL` в обоих полях; никакое название не восстанавливается догадкой. `caller_phone` сохраняет строку в исходном представлении, без предположения о едином национальном формате. Оно обозначает номер, указанный при конкретном обращении, а не проверенный Caller ID. Контакты NetUP лишь предлагаются для выбора; snapshot BillingProvider остаётся отдельным источником.

## Создание

В связанном пути оператор вводит ЛС, проверяет найденную карточку, выбирает тему и при необходимости номер из контактов NetUP или иной номер. Дополнительный комментарий необязателен; при его отсутствии `description` получает выбранную тему или уточнение «Другое», поскольку старый Ticket Engine требует непустое описание. Без `category_id` прежний API продолжает требовать `description`. Manual и internal заявки сохраняют свободную форму и могут использовать категорию как необязательное дополнение через API.

Проверка дубликата по идентификатору абонента, явная причина другой проблемы, выбор нескольких услуг/подключений и `client_request_id` остаются обязательными. Операторские права чтения заявок других сотрудников определяются существующим `tickets.read.all`; справочник не расширяет их. Номер звонящего и категория видны только обладателю права чтения соответствующей заявки.

## Эксплуатация

Миграция не изменяет существующие строки заявок. Перед применением на dev требуется защищённый `pg_dump` и проверенное восстановление в отдельную временную `oss_test_*` базу. Справочник не содержит секретов. Резервная копия базы может содержать персональные данные и хранится вне Git с правами `0600`.
