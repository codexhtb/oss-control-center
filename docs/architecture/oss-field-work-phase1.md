# OSS Field Work — этап 1: backend Mini App

## Модель данных

Миграция `0046_field_installers` добавляет `field_installers` (стабильный Telegram user ID,
имя, активность, время создания/обновления) и `field_installer_directions` (доступ к SUKHUM
и/или OCHAMCHIRA). Доступ определяется только этим реестром PostgreSQL. Профиль Telegram
не может самостоятельно назначить направление. Исторические `field_work_handoffs` не меняются;
очередь адресует каждый handoff по его UUID, поэтому повторные выезды по одной заявке
остаются отдельными строками.

## API contract и права

Все пути начинаются с `/api/v1/field-work`.

- `POST /installers`, `PUT /installers/{id}` — OSS-сессия, CSRF/Origin и существующее
  персональное разрешение `users.manage`. `GET /installers` — OSS-сессия и `users.manage`.
  Изменение требует `expected_updated_at`; удаление заменяется отключением `is_active=false`.
- `GET /miniapp/me`, `GET /miniapp/handoffs?queue=open|completed|history&direction=...&page=...&page_size=...`,
  `GET /miniapp/handoffs/{handoff_id}` — заголовок `X-Telegram-Init-Data` с исходной строкой
  Telegram `initData`. Никаких OSS cookie или прав администратора для монтажника не требуется.
  Ответы имеют `Cache-Control: no-store`.
- Очереди соответствуют `AWAITING_REPORT`, `REPORTED`, `VERIFIED`. Видны только handoff
  с `delivery_status=SENT` и подтверждённым направлением из реестра. Заявки `INTERNAL`
  и удалённые заявки исключены. Пагинация ограничена 100 строками; сортировка стабильна.
  Детали включают только необходимый контакт из заявки/сохранённого snapshot и причину
  передачи. Сырые Telegram-сообщения, историю, аудит и финансовые поля API не выдаёт.

`initData` проверяется на backend HMAC-SHA-256 по токену существующего бота, включая
`auth_date` (максимум один час, допустимо 30 секунд в будущем). Дубли ключей, неверная
подпись и неактивный монтажник отклоняются. Токен читается только из защищённого
`TELEGRAM_BOT_TOKEN_FILE`, не возвращается клиенту и не хранится в новой таблице.

## Workflow и acceptance

Этот этап только читает выезды; текущие Telegram-кнопки, отчёты и переходы статусов не
изменяются. Администратор OSS регистрирует Telegram ID и направления; монтажник с
подписанным `initData` видит общую очередь своего направления и конкретное задание.
Отключение записи немедленно отзывает доступ. Неподписанный запрос, чужое направление,
удалённая или внутренняя заявка не раскрываются. Перед этапом 2 необходимо отдельно
реализовать интерфейс, отправку отчётов и переносы через Mini App.
