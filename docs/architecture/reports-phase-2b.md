# Reports Phase 2B — монтажные работы и причины обращений

Read-only API `GET /api/v1/reports/field-work` и `GET /api/v1/reports/reasons` используют включительные даты UTC+3 (`start`, `end`), пагинацию `page`/`size` и прежний доступ `reports.read` вместе с `tickets.read.all` или `tickets.read.own`. Оператор с выданным правом всё равно не видит INTERNAL; удалённые заявки исключаются до агрегации. При `read.own` учитываются только созданные пользователем заявки.

`field-work` принимает необязательный `direction=SUKHUM|OCHAMCHIRA`. Количество отправленных, полученных отчётов и проверенных работ — число handoff с `sent_at`, `reported_at`, `verified_at` в периоде соответственно. Уникальные заявки для отправленных handoff считаются отдельно. Каждый `field_work_reschedules.created_at` — отдельное событие; число handoff с переносами отдельно, JOIN истории не умножает отправки. Дневные агрегаты используют время каждого события. `awaiting_report_now` и `date_pending_now` — текущие состояния отправленных handoff, независимо от дат фильтра. Handoff без направления показывается как UNKNOWN, без предположений о группе. Детализация включает handoff с любым событием периода и ведёт в заявку.

`reasons` принимает необязательное точное историческое `category` и `detail_kind=category|decision`. Категории и их дневная динамика считаются по `tickets.created_at` и названию при регистрации. Если категорию позже исправили, берётся `before` из первого события `ticket_edited` с изменением `category_name` в `ticket_history`; без такого события берётся сохранённый `tickets.category_name`. Причины считаются по каждому `ticket_decisions.created_at` и сохранённому `reason_name`; повторные решения — отдельные события, уникальные заявки считаются отдельно. Показатель «Созданные, без установленной причины сейчас» — текущий снимок когорты созданных за период заявок; он может измениться после нового решения. Детализация переключается между созданными заявками и отдельными решениями с независимой пагинацией событий.

Приёмка: повторный перенос не увеличивает число отправленных handoff; поздний отчёт и проверка попадают в дату своего события; исторические категории и причины не заменяются названиями справочников; при нескольких решениях счётчик событий больше числа уникальных заявок; INTERNAL и удалённые заявки не попадают ни в метрики, ни в детализацию.
