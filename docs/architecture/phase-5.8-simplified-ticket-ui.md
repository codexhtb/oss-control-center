# Phase 5.8 — упрощённая карточка и причины решения

Карточка использует один общий поток комментариев. Создание новых ручных
diagnostic snapshots через UI прекращено, но API, права и исторические записи
сохраняются. Технические записи, версии решений, события и завершённые обзвоны
показываются в свёрнутых секциях и загружаются только после раскрытия. Текущий
вердикт для `RESOLVED` загружается сразу, потому что нужен контрольному обзвону.

Миграция `0018_resolution_reasons` добавляет nullable `ticket_decisions.reason`
и делает прежний `performed_actions` nullable. Старые строки не дополняются
догадками: у них `reason IS NULL`, а прежний текст действий сохраняется. Новые
клиенты отправляют свободный `decision_text` и одну структурированную причину:

- `CABLE_BREAK`, `CUSTOMER_EQUIPMENT`, `ONU_POWER`, `NETWORK_FAULT`;
- `CONFIGURATION_IP`, `CONNECTION_SETUP`, `CONSULTATION`, `OTHER`;
- `NOT_ESTABLISHED`.

Для обратной совместимости `performed_actions` по-прежнему принимается, но не
обязателен. Если прежний клиент не отправил `reason`, backend явно сохраняет
`NOT_ESTABLISHED`; это не классификация по тексту, ONU или мониторингу. Каждая
новая версия решения хранит собственную причину и остаётся неизменяемой.
