# Phase 5.7 — контрольный обзвон и закрытие

`RESOLVED` связанной с абонентом заявки означает ожидание контрольного звонка.
Очередь вычисляется сервером из неудалённых `SUBSCRIBER_LINKED` заявок в
`RESOLVED`, по возрастанию `resolved_at`. Телефоны и имя берутся только из
сохранённого snapshot заявки и `caller_phone`; очередной NetUP lookup не нужен.

Каждый звонок — отдельная неизменяемая строка `ticket_callbacks`, связанная с
конкретной версией инженерного решения (`decision_id`), автором и точным
`occurred_at`. `client_request_id` уникален в рамках заявки и защищает от
повторной записи при повторе HTTP-запроса. PostgreSQL транзакция одновременно
создаёт звонок, меняет статус и версию заявки, записывает историю и аудит.
`If-Match` и блокировка строки заявки разрешают только один результат для
одной версии при конкурентных действиях. Повтор с тем же ID и тем же
содержимым возвращает текущее состояние; другое содержание даёт `409`.

| Результат | Переход | Обязательные данные |
| --- | --- | --- |
| `NO_ANSWER` | `RESOLVED → RESOLVED` | Автор и время; комментарий по желанию |
| `STILL_BROKEN` | `RESOLVED → IN_PROGRESS` | Комментарий абонента; исполнитель снимается |
| `CONFIRMED` | `RESOLVED → CLOSED` | Автор и время подтверждения |

После возврата инженерам новая попытка решения создаёт новое неизменяемое
`ticket_decisions`; первый вердикт и предыдущие звонки сохраняются. `IN_PROGRESS`
без исполнителя попадает в очередь ожидания инженера Phase 5.5.

`POST /close` не закрывает связанные заявки. Для `MANUAL` и `INTERNAL` он
сохраняется как отдельный путь с `tickets.close`, текущим `decision_id`,
`If-Match` и обязательной причиной закрытия без абонентского звонка. Причина
остаётся в истории; фиктивное подтверждение звонка не создаётся. Исторические
закрытые заявки миграция не изменяет.

Для контрольного обзвона требуется индивидуальное `tickets.callback` вместе с
`tickets.read.all` для обзора очереди. Роль `operator` не получает это право
автоматически. Владелец назначит его настоящему аккаунту Симы после
идентификации; логин и пароль в коде не фиксируются. Инженер по умолчанию
сохраняет `tickets.resolve`, но не получает `tickets.callback` автоматически.
Администратор получает новое право по умолчанию. Изменение грантов действует
при следующем API-запросе; сервис перечитывает и блокирует пользователя
перед мутацией.
