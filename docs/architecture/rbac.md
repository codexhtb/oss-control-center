# RBAC matrix

В приложении только две роли: `CALL_CENTER_OPERATOR` и `OSS_ENGINEER`. Два сетевых инженера OSS имеют одинаковые права. Монтажный сектор не получает учётных записей и работает через Telegram с Phase 3. Техническое предварительное создание/отключение локальных учётных записей выполняется вне продуктового workflow; роль администратора не вводится.

| Действие | Оператор call-центра | Инженер OSS | Монтажный сектор |
| --- | :---: | :---: | :---: |
| Войти в OSS Control Center | Да | Да | Нет |
| Найти Subscriber 360 по лицевому счёту | Да | Да | Нет |
| Просмотреть заявки и историю | Да | Да | Нет |
| Создать заявку | Да | Нет | Нет |
| Добавить комментарий к открытой заявке | Да | Да | Нет |
| Начать работу по заявке | Нет | Да | Нет |
| Записать ручной диагностический snapshot | Нет | Да | Нет |
| Записать/изменить решение новой версией | Нет | Да | Нет |
| Закрыть заявку с решением | Нет | Да | Нет |
| Читать аудит по заявке | Нет | Да | Нет |
| Подтвердить и отправить FieldWorkHandoff (Phase 3) | Нет | Да | Нет |
| Проверить ответ о работах (Phase 3) | Нет | Да | Нет |
| Ответить в согласованном Telegram чате (Phase 3) | Нет | Нет | Да |

Чтение заявок обоими ролями ограничено одним организационным контуром; межорганизационная модель и дополнительные роли не вводятся. Закрытая заявка в Phase 1 доступна для чтения, но не для новых комментариев, наблюдений или решений. Сервер проверяет роль и состояние ресурса при каждом запросе, фиксирует разрешённые изменения и отказы доступа в аудите. Интерфейс скрывает недоступные действия, но не заменяет серверную проверку.

Получение Telegram сообщения от монтажника не даёт отправителю роль `OSS_ENGINEER` и не разрешает закрытие заявки. Решение и закрытие требуют аутентифицированного действия инженера в OSS Control Center.
