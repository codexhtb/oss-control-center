# RBAC и персональные разрешения

Текущий контракт — [Identity, Permissions & Ticket Editing](phase3-identity-ticket-editing.md).
Роль `operator`, `engineer`, `admin` задаёт начальный профиль при создании сотрудника;
после этого авторизация опирается на сохранённые индивидуальные разрешения. Отзыв
права применяется к действующей сессии при следующем запросе. UI скрывает действия,
но сервер независимо проверяет каждое действие и доступ к ресурсу.

| Возможность | Ключ разрешения | Operator по умолчанию | Engineer по умолчанию | Admin по умолчанию |
| --- | --- | :---: | :---: | :---: |
| Просмотр/управление сотрудниками | `users.read` / `users.manage` | — | — | Да / Да |
| Активные темы / управление справочником тем | `tickets.create` / `users.manage` | Да / — | Да / — | Да / Да |
| Создание заявок всех типов | `tickets.create` | Да | Да | Да |
| Просмотр всех/своих заявок | `tickets.read.all` / `tickets.read.own` | Да / — | Да / — | Да / Да |
| Изменение всех/своих заявок | `tickets.edit.all` / `tickets.edit.own` | — / Да | Да / — | Да / Да |
| Комментарии | `tickets.comment` | Да | Да | Да |
| Удаление своих/любых заявок | `tickets.delete.own` / `tickets.delete.all` | — / — | — / — | Да / Да |
| Корзина и восстановление | `tickets.restore` + `tickets.read.all` | — | — | Да |
| Окончательное удаление | `tickets.purge` + `tickets.read.all` | — | — | Да |
| Назначение и начало работы | `tickets.assign` / `tickets.start` | — | Да | Да |
| Диагностика, решение, закрытие | `tickets.diagnose` / `tickets.resolve` / `tickets.close` | — | Да | Да |
| Причина передачи монтажникам | `tickets.field_work` | — | Да | Да |
| Subscriber 360 | `subscribers.read` | Да | Да | Да |
| Финансовые поля биллинга | `subscribers.finance.read` | Да | — | Да |
| Чтение/запуск диагностики | `diagnostics.read` / `diagnostics.run` | Да / — | Да / Да | Да / Да |
| Чтение аудита | `audit.read` | — | Да | Да |

Права чтения и изменения заявки независимы: `tickets.edit.own` не даёт
возможности прочитать чужую заявку. `tickets.read.own` ограничивает видимость
создателем; назначение исполнителя не делает его автором. Для инженерных
действий нужны соответствующее индивидуальное право и видимость заявки.
Закрытая заявка доступна для чтения и неизменна; решение и закрытие остаются
отдельными действиями с workflow `OPEN → IN_PROGRESS → CLOSED`.

При проверке повторных обращений по абоненту `subscribers.read` разрешает
получить только факт существования недоступной активной заявки. Сводка
доступна по `tickets.read.all` или для своей заявки по `tickets.read.own`.
Создание второй связанной заявки при подтверждённой другой проблеме требует
`tickets.create` и причины; это не расширяет права чтения чужой заявки.

Технический `admin` больше не исключён из Service Desk: владелец проекта
утвердил полный доступ по умолчанию. Это не новое подразделение и не маршрут
эскалации. Запрет удаления/деактивации последнего активного администратора
сохранён; нельзя отозвать последний грант `users.manage`. Административные
действия фиксируются в `identity_audit_events` без секретов.

Монтажный сектор не имеет кабинета OSS Control Center. Telegram Field Dispatch
остаётся отдельным будущим этапом; ответ монтажника не закрывает заявку.
