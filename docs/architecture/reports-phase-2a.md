# Reports Phase 2A — сотрудники и контрольные звонки

Новые read-only API: `GET /api/v1/reports/employees` и `GET /api/v1/reports/callbacks`.
Оба принимают включительные `start` и `end` (`YYYY-MM-DD`, UTC+3); диапазон до 3660 дней.
`callbacks` дополнительно принимает `page` и `size` (1–100), по умолчанию 1 и 20.
Контракт доступа совпадает с Phase 1: `reports.read` вместе с `tickets.read.all` либо
`tickets.read.own`. При `read.own` учитываются только заявки, созданные сотрудником.
Для оператора `INTERNAL` исключён из каждого агрегата и страницы детализации.
Удалённые заявки исключены. Пустые периоды возвращают нули и пустые списки.

## Правила расчёта

- Сотрудники: созданные заявки группируются по `tickets.created_by` и `created_at`;
  решения — по `ticket_decisions.engineer_id` и `created_at`; контрольные звонки —
  по `ticket_callbacks.actor_id` и `occurred_at`. Текущий исполнитель заявки не
  используется. Повторное решение и повторный звонок учитываются как новые события.
- Для каждого сотрудника возвращаются число созданных заявок, число событий решений,
  число событий звонков, число уникальных заявок с звонками, распределение исходов
  и разреженные дневные агрегаты действий. При полном доступе доступны все сотрудники,
  включая отключённых; при `read.own` — только авторы видимых действий.
- Контрольные звонки считаются непосредственно из `ticket_callbacks`:
  `CONFIRMED` — проблема устранена, `STILL_BROKEN` — проблема осталась,
  `NO_ANSWER` — не дозвонились. Возвращаются число событий и уникальных заявок,
  распределение по исходам, дню и сотруднику, а также страница отдельных звонков
  со ссылками на заявки. Агрегация выполняется SQL в PostgreSQL; строки событий
  выбираются только для страницы детализации.

Приёмка: событие относится к фактическому автору; два звонка по одной заявке
дают два события и одну уникальную заявку; при смене календарного дня UTC+3
событие попадает в верную дату; удалённые и недоступные INTERNAL не учитываются;
страница детализации совпадает с агрегатами и не раскрывает чужие заявки.
