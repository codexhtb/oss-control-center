# Subscriber360: реквизиты личного кабинета NetUP

Логин читается сразу при открытии обзора отдельным GET-запросом. Пароль
читается только по нажатию глаза отдельным POST с session, Origin и CSRF.
Копирование пароля доступно только после раскрытия. Маска имеет постоянную
длину и не содержит пароль в DOM/атрибутах. После скрытия, ухода с обзора,
смены карточки, скрытия вкладки или 60 секунд пароль удаляется из состояния.
React Query используется только для логина: секрет не попадает в query/mutation
cache, browser storage, snapshots, PostgreSQL или журналы.

## API и workflow

- `GET /api/v1/subscriber-lookups/{lookup_id}/cabinet` →
  `{login, password_available}`. Требует `subscribers.read`, собственный lookup
  и источник NETUP. Запрос не выбирает парольную колонку.
- `POST /api/v1/subscriber-lookups/{lookup_id}/cabinet/password` → `{password}`.
  Дополнительно требует `subscribers.password.read`, свежий lookup, CSRF и Origin.
  Нет права → 403, чужой lookup → 404, истёкший → 409,
  отключение/ошибка источника/неподдерживаемый encrypted → безопасный 503.
- Все ответы API имеют `Cache-Control: no-store`; успешный парольный ответ
  дополнительно `Pragma: no-cache`. Текст DBAPI-ошибок не возвращается.
- `accounts.id → users_accounts.account_id → users_accounts.uid → users.id`:
  все объекты неудалённые, ровно один владелец; он должен совпасть с
  `snapshot.subscriber_id`. Сначала проверяются все владельцы, затем ожидаемый
  user_id. Смена владельца/неоднозначность прекращает чтение.
- Пароль выбирается только после проверки владельца; допускается только
  `users.encrypted=0`, непустой `users.password`. Никакого восстановления,
  подбора, сброса, генерации PDF или изменения NetUP.
- После внешнего I/O повторно проверяются активность сотрудника, сессия и
  сохранённые разрешения. До выдачи обязательно фиксируется аудит
  `subscriber_password_view`: actor, время, outcome, только lookup UUID.
  Ошибка сохранения аудита не допускает выдачи секрета.

## Модель данных и RBAC

Снимки Subscriber360 и BillingProvider не меняются. Login/password загружаются
вне модели snapshot. `CabinetCredentials` имеет отключённый repr и `SecretStr`.
Единственная миграция OCC `0054_subscriber_password` расширяет допустимый
набор permissions. Она не добавляет парольных колонок и никому не выдаёт право.
По запросу владельца от 25.11.2026 preset оператора включает
`subscribers.read` и `subscribers.password.read`; существующим неудалённым
операторам оба права добавляются транзакционно с аудитом, без отзыва других
персональных grants. Ранее назначенные права остальных ролей сохраняются.
RBAC остаётся серверным и персональным, право можно отозвать редактором.
Режим источника и назначение права независимы: выключенная выдача блокирует
сам парольный API, а не редактирование grants. До выдачи нового enum обновляется
Telegram worker до совместимого image; offset Telegram сохраняется в PostgreSQL.
Схема/данные NetUP и репликация не изменяются.

## Включение и критерии приёмки

По умолчанию `SUBSCRIBER_CABINET_MODE=disabled`: логин работает, пароль недоступен.
Для рабочего портала владелец 25.11.2026 явно отменил обязательное шифрование
SQL и принял риск существующей management-сети. Режим `management` вместе с
`NETUP_ALLOW_PLAINTEXT_MANAGEMENT=true` допускает только `172.17.7.1:3307`,
production-purpose, без исторического as_of и lab plaintext flag. API остаётся
HTTPS. Перед чтением пароля проверяются `server_id=2` и `read_only=1`.
TLS/SSH не являются условием раскрытия в этом режиме. Туннели, ключи,
сертификаты и дополнительные транспортные сервисы не создаются.

Отдельный режим `verified` по-прежнему требует одновременно
`SUBSCRIBER_CABINET_MEMO_VERIFIED=true`, TLS CA с проверкой сертификата/имени
и непустой `Ssl_cipher` именно в соединении, читающем пароль. Любое невыполненное
условие блокирует выдачу в режиме `verified`. Владелец выполнил ручную DEV-проверку
и запросил production-включение; реальные реквизиты в отчёты не включаются.

Для ручной проверки существует явно выделенный `dev_preview`: только
APP_ENV dev/test, лабораторный NetUP config, отдельный HTTPS-порт (не 443/8443).
Это временное исключение для существующего private lab SQL-канала; оно
не подтверждает TLS и не является разрешением на production-выдачу.
Рабочий портал исторически имеет APP_ENV=dev, поэтому дополнительно проверяется
выделенный origin/порт. Текущий production promotion явно включает `management`.

Автоматические тесты используют только синтетические значения: SELECT без
пароля для login, несколько счетов/смена владельца/неоднозначность, unknown
encrypted, отсутствие TLS/подтверждения, все роли без персонального права,
CSRF, отзыв права/сессии/аккаунта во время I/O, аудит без секрета, отсутствие
секрета в snapshot/логах/React Query, раскрытие/копирование/очистка и поздний ответ.
