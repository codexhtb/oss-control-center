# Backup и restore PostgreSQL

PostgreSQL хранит критичные данные OCC; named volume не является backup. Не удаляйте и не пересоздавайте volume как способ восстановления.

## Backup gate

Перед schema/runtime изменением владелец должен подтвердить backup, его защищённое расположение и владельца. Архив может содержать PII: доступ и срок хранения ограничиваются локальной политикой; не копируйте его в Git, issue, общий лог или публичный каталог.

В качестве безопасной валидации существующего custom-format архива:

```bash
pg_restore --list "$BACKUP_FILE" >/dev/null
sha256sum "$BACKUP_FILE"
```

Эти проверки не доказывают возможность восстановления. Зафиксируйте размер/контрольную сумму/время в защищённом backup register без выгрузки данных.

## Restore

Restore разрешён только в заранее созданную изолированную PostgreSQL, не в рабочий volume. Перед restore подтвердите версию PostgreSQL, extensions, locale, ownership mapping, свободное место и отсутствие маршрута приложений к этой БД. После restore сравните Alembic revision и обезличенные контрольные количества основных сущностей; откройте выборочные записи только уполномоченному reviewer.

Точная команда и целевой isolated environment для текущего production **UNVERIFIED**; подтвердить практическим restore exercise. Не публикуйте универсальную команду `pg_restore` без однозначного указания isolated target. Полный DR не подтверждён.
