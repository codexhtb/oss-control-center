# Управление секретами

## Хранение

Секреты владельца и технические credentials хранятся вне Git и Docker image. Инструкции проекта задают owner-controlled vault `/root/oss-secrets/`, каталог не шире `0700`, файл не шире `0600`. Runtime может получать отдельные read-only mounts/protected files; не копируйте значения в `.env`, документацию, CI output или shell arguments.

## Реестр и владение

Для каждого созданного секрета владелец ведёт имя/назначение, компонент, ответственного, дату выдачи/ротации, место безопасного backup и процедуру revoke. Значения и полный список секретных путей не публикуются в общих логах. Владелец должен уметь восстановить доступ или заменить credential.

## Проверка и ротация

- Проверяйте только наличие файла, owner и mode (`stat`), не печатайте содержимое.
- Ротацию выполняйте с явным owner approval, с периодом перекрытия, проверкой сервиса и подтверждённым revoke старого credential.
- TLS private key, Telegram token, NetUP/monitoring credentials и auth hash key принадлежат разным trust boundaries; не переиспользуйте.
- Перед изменением runtime mount проверьте compose labels и зависимые контейнеры; не перезапускайте сервисы без разрешения.

В рамках repository overhaul секреты не создавались, не читались и не менялись. Проверенное резервное копирование secret store в этой задаче не выполнялось; status резервирования — **UNVERIFIED**. Подтверждает владелец vault по своему защищённому inventory.
