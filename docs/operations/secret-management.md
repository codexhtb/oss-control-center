# Учётные данные OSS Control Center

Владелец инфраструктуры должен иметь доступ к каждому паролю БД,
техническому аккаунту, API-токену, SSH-ключу и сервисному credential,
созданному для проекта. Значения секретов никогда не помещаются в Git,
документы, отчёты, терминальный вывод или общие логи.

## Хранение и реестр

- Предпочтительное место владельца: `/root/oss-secrets/`, каталог `0700`,
  файлы секретов и реестр `0600`, владелец `root`. Реестр содержит только
  метаданные: `system`, `host`, `account`, `purpose`, `secret_path`,
  `created_or_changed_at`, `recovery_or_rotation`, `backup_reference`.
  Значения секретов и хеши в реестр не записываются.
- Если процессу под `codexdev` нужен runtime-файл, хранить отдельную копию
  в согласованном игнорируемом Git пути с режимом `0600`; внести оба пути
  в реестр. `root` может прочитать такой файл. Не переносить секреты через
  чат, командные аргументы или переменные в shell history.
- Перед созданием проверять существующий реестр и файлы. Не перезаписывать
  ключи, токены и пароли; ротацию делать только по необходимости и после
  согласования. Учётная запись без доступного владельцу способа получения
  или смены секрета не считается готовой.
- По окончании этапа сообщать владельцу **метаданные** новых или изменённых
  секретов: систему, хост, аккаунт, назначение, путь, способ получения и
  состояние резервной копии. Если новых секретов нет, это отмечается явно.

## Команды для администратора

`codexdev` не имеет доступа к `/root/oss-secrets/`. Администратор создаёт
каталог и пустой реестр без вывода или перезаписи значений секретов:

```bash
sudo install -d -o root -g root -m 0700 /root/oss-secrets
sudo touch /root/oss-secrets/registry.tsv
sudo chown root:root /root/oss-secrets/registry.tsv
sudo chmod 0600 /root/oss-secrets/registry.tsv
```

После проверки текущего реестра администратор добавляет строку метаданных
для каждого существующего или нового файла. Для уже подготовленного
лабораторного доступа UTM5 строка должна указывать `netup-db-lab`,
`172.17.7.1`, `oss_netup_lab`, назначение «read-only лабораторные тесты» и
`/opt/oss-control-center/.env.netup-lab`. Сам пароль в реестр не копируется.
После проверки отсутствия такой строки точная команда добавления:

```bash
printf '%s\t%s\t%s\t%s\t%s\t%s\t%s\t%s\n' \
  'UTM5 lab' '172.17.7.1' 'oss_netup_lab' \
  'read-only integration tests' '/opt/oss-control-center/.env.netup-lab' \
  '2026-10-13' 'root reads file; rotate in lab MariaDB' 'backup pending' \
  | sudo tee -a /root/oss-secrets/registry.tsv >/dev/null
```

## Резервное копирование и восстановление

Каталог владельца включать в согласованное **зашифрованное** резервное
копирование с доступом только владельцу. Ключ расшифрования хранить отдельно
от копии и исходного хоста. После настройки проверять восстановление в
изолированном месте, права `0700/0600` и полноту реестра. Runtime-копии
секретов сверять с реестром; их не следует считать единственной резервной
копией. До подтверждения владельцем нельзя отмечать резервное копирование
как выполненное.
