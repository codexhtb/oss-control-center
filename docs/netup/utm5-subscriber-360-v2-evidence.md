# NetUP UTM5: доказательная проверка для Subscriber 360 v2

Дата проверки: 2026-11-04. Объект: восстановленная лабораторная копия UTM5,
опубликованная как снимок от 2026-10-10. Это **не** действующая реплика.
Приложение и обе базы данных не изменялись: использованы только `SELECT` в
`START TRANSACTION READ ONLY` и чтение документации. Данные абонентов, номера
счетов, суммы и секреты в отчёт не включены. Версия ядра, создавшего копию,
не найдена; поэтому документация 5.3 и 5.5 — доказательство поведения продукта,
а соответствие конкретному полю копии дополнительно проверено SQL.

Источники: [руководство администратора UTM5 5.3-006, PDF](https://www.netup.ru/ru/utm5/utm5docs/UTM-5.3-006_rus.pdf)
(далее **Р**, страницы 18–26, 110, 202),
[официальные правила архивации](https://www.netup.tv/en/utm5/tables)
(**А**), [изменения версий](https://www.netup.ru/ru/utm5/change)
(**И**), [руководство 5.5-033](https://www.netup.ru/ru/utm5/utm5docs/5.5-033-release-web/index.html)
(**Н**). SQL-свидетельство ниже обозначено **Б** и воспроизводится запросами
в конце отчёта. Уверенность «высокая» означает прямую документацию и/или
однозначное соотношение в копии; «средняя» — сильную корреляцию без спецификации
поля; «низкая» — гипотезу, **не готовую к реализации**.

## Что проверено сверх прежнего аудита

- В доступной файловой системе не найдено установленного дерева `/netup/utm5`,
  конфигурации ядра, его SQL-скриптов или исходного кода. Найдены только файлы
  адаптера OSS, закрытые файлы реквизитов лаборатории (не читались и не
  публиковались) и локальная SQL-обёртка. В схеме копии нет routines, views,
  triggers и events, которые могли бы расшифровать коды.
- Руководство 5.3 прямо подтверждает 0/256/768 и `int_status`; поиск по
  официальным руководствам 5.3/5.4/5.5 и changelog **не дал** таблицы
  соответствия 16/48, SQL-`block_type`/`flags` или полного справочника
  `charge_type`. Выводить эти значения из одного лишь битового представления
  небезопасно.
- Расхождение между 1866 ссылками `block_id` при `is_blocked=0` и
  документированным кодом «не заблокирован» доказывает, что один join на
  `blocks_info` не является достаточным правилом текущего состояния.
- `cost_coef=1.0` преобладает; это **не** отменяет схему коэффициентов,
  пересчёт и налоги. «Внешний IP» присутствует среди дополнительных услуг,
  но его фактическая плата может отличаться от каталожного `cost`.

## Воспроизведение без персональных данных

Все запросы запускать только с read-only учётной записью к лабораторной копии,
в read-only транзакции. Примеры возвращают только коды и количества:

```sql
START TRANSACTION READ ONLY;
SELECT is_blocked, int_status, COUNT(*)
  FROM accounts GROUP BY is_blocked, int_status;
SELECT a.is_blocked, b.block_type, b.flags, b.is_deleted, COUNT(*)
  FROM accounts a JOIN blocks_info b ON b.id=a.block_id
  GROUP BY a.is_blocked, b.block_type, b.flags, b.is_deleted;
SELECT charge_type, service_type, SIGN(discount), COUNT(*)
  FROM discount_transactions_all
  GROUP BY charge_type, service_type, SIGN(discount);
SELECT is_canceled, SIGN(payment_absolute), COUNT(*)
  FROM payment_transactions GROUP BY is_canceled, SIGN(payment_absolute);
SELECT currency_id, COUNT(*) FROM payment_transactions GROUP BY currency_id;
SELECT COUNT(*) FROM archives;
SELECT table_name FROM information_schema.tables
  WHERE table_schema=DATABASE()
    AND (table_name LIKE 'discount_transactions_all_%'
      OR table_name LIKE 'payment_transactions_%' OR table_name LIKE 'user_log_%');
ROLLBACK;
```

## Минимальные вопросы специалисту биллинга

1. Какую **точную сборку UTM5** создала резервную копию? Нужен её словарь
   `accounts.is_blocked` для 16/48, `blocks_info.block_type` 1/2 и `flags`
   0/1/2; достаточно документа схемы/констант либо трёх обезличенных счетов
   с подтверждёнными в GUI административной, пользовательской и системной
   блокировками и соответствующими SQL-полями.
2. Как в этой сборке именуются `discount_transactions_all.charge_type`
   1/2/3/16/17/18/22/23 и какие записи составляют платеж, сторно, возврат и
   корректировку? Достаточно по одному обезличенному контрольному событию
   каждого вида с ID операции в GUI и строками обеих таблиц без ФИО/сумм.
3. Какая валюта и точность применяются к `cost`, `discount`,
   `payment_incurrency`, `payment_absolute` и историческому коду валюты 643?
   Нужен один обезличенный счёт с тарифом и «Внешним IP», периодом,
   коэффициентами, политикой, отображаемой ценой и начислением за полный и
   неполный период. Это также позволит проверить формулу итоговой платы.
4. Сохраняются ли в рабочей версии все старые `user_log` и удалённые
   `service_links` с датами отключений, существуют ли внешние архивы? Нужен
   один обезличенный абонент с известной датой первого подключения,
   сменой/отключением услуги и сверкой доступных строк с GUI.

До этих сверок в Subscriber 360 нельзя показывать недоказанные финансовые
итоги или объявлять историю полной. Источник `NETUP`, время снимка и качество
`STALE`/`UNKNOWN`/`CONFLICT` должны сохраняться раздельно; OSS PostgreSQL
остаётся источником истины только для заявок OSS.
