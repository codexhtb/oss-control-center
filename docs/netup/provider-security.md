# Модель безопасности NetUP provider

**Граница доступа:** HTTP lookup требует `subscriber.read`, серверную
сессию и CSRF. Администратор Identity не получает автоматического доступа.
Для production целевой SQL-пользователь должен иметь column-level SELECT
только на нужные поля, без прав на столбцы паролей и административные
таблицы. Текущая изолированная лабораторная учётная запись имеет более
широкие `SELECT, SHOW VIEW`; адаптер выбирает только перечисленные поля
подтверждённых таблиц. Каждое чтение
выполняется с `REPEATABLE READ` в
`START TRANSACTION WITH CONSISTENT SNAPSHOT, READ ONLY` с
параметрами DBAPI (`%s`), серверным `max_statement_time`, connect/read
timeout, общим дедлайном и лимитами строк. Имя таблицы и SQL не строятся из
ввода пользователя. ЛС проверяется до соединения с UTM5.

**Конфиденциальность:** в памяти адаптера есть реальные ФИО, контакты,
адреса, IP-числа и сетевые привязки. Они попадают только в авторизованный
ответ и immutable PostgreSQL snapshot. Не логировать SQL-параметры, сырые
строки, объекты DTO, DSN или текст DBAPI-ошибок. Ошибки сворачиваются в
безопасные коды; аудит lookup сохраняет actor/outcome без ЛС и PII.
Production TLS CA и пароль хранятся вне Git; `SecretStr` маскирует repr
конфигурации. Plaintext допускается только как явное лабораторное исключение
для private IP и отдельного lab user, без production реквизитов.

**Целостность:** отсутствующий, неоднозначный или неполный источник не
порождает snapshot. Snapshot и его дочерние строки записываются в одной
PostgreSQL транзакции и неизменяемы триггером. Выбор услуги и подключения
проверяется по сохранённому snapshot и их связи. `NETUP` не смешивается с
`MOCK` и не определяет состояние линии. Неизвестные IP-коды остаются raw
числами с quality `UNKNOWN`, а не декодированным публичным адресом.

**Остаточный риск:** нынешний API возвращает авторизованному оператору все
исходные raw IP-числа. Перед Web UI нужен review отображения и доступа к
этому полю; UI не должен показывать их как проверенный IPv4. Строгие клиенты
должны принимать добавочные поля. Провести нагрузочный тест по отсутствующему
индексу `users_accounts.account_id` перед production включением.
