# UTM5: технические параметры и границы их значения

Проверки выполнены на копии UTM5 от 2026-10-10. Метаданные и агрегаты:
[`30_network.sql`](sql/30_network.sql). Ни один IP, MAC, hostname или строка
конкретного абонента не сохранены в этом репозитории.

## Проверенная цепочка

`service_links.id` (тип 3) → `iptraffic_service_links.id` →
`iptraffic_service_links.ip_group_id` → `ip_groups.ip_group_id`.

**VERIFIED:** 2 841 неудалённая IP-связь имеет одну ссылку на группу; ссылки
уникальны между активными услугами. Группа содержит от 1 до 68 неудалённых
строк. `ip_groups.id` — ID отдельной строки, **не** ID всей группы.

| Наблюдение на 2 841 группах | Число | Оценка |
|---|---:|---|
| Нет ненулевых switch/port/VLAN | 9 | **UNKNOWN** для этих полей |
| Ровно одна различная полная тройка | 2 824 | **INFERRED** кандидат подключения после проверки семантики `port_id`/`vlan_id` |
| Несколько полных троек | 8 | **CONFLICT**, нельзя выбрать первую/минимальную |
| Группы с более чем одной строкой | 1 705 | Требуется свёртка по группе; 1 695 групп содержат и заполненные, и нулевые `switch_id` в разных строках |

Среди 4 920 неудалённых строк групп у 2 876 одновременно указаны положительные
switch/port/VLAN; все 2 876 `switch_id` находят неудалённый `switches.id`.
Все положительные `port_id` находятся в пределах `switches.ports_count`, все
положительные `vlan_id` — в диапазоне 1–4094 (**VERIFIED** как числовая
проверка; это всё ещё не доказательство физического обозначения порта/VLAN).
У всех 296 неудалённых коммутаторов есть неудалённый `switch_types`.

**CONFLICT:** `users.remote_switch_id/port_number` заполнены у 214 активных
IP-связей; для 212 соответствующая IP-группа имеет единственные ненулевые
switch/port, но оба значения расходятся с `users`. Совпадений нет. Не
использовать эти пользовательские поля как fallback для топологии.

## IP, MAC и тип доступа

- **VERIFIED:** 1 806 из 2 841 живых групп имеют хотя бы одно ненулевое
  `ip_groups.ip`, 1 035 — ни одного. У 128 групп несколько разных IP.
  `ip_ext` и `mask_ext` не заполнены ни в одной живой строке.
- **UNKNOWN:** `ip_groups.ip` хранится числом; 140 живых строк имеют
  отрицательное значение при signed BIGINT. Способ декодирования IP и смысл
  `ip_type` (наблюдались коды 0, 1, 4) не подтверждены. Не печатать и не
  преобразовывать IP в карточке до проверки формата владельцем UTM5.
- **VERIFIED:** `ip_groups.mac` пуст во всех 4 920 живых строках.
  `dhcp_leases` содержит 1 815 записей с MAC, но лишь 85 арендами, не
  истёкшими к концу дня копии. Связь по IP есть у 1 737 групп за всё время,
  но динамическая аренда не доказывает постоянный MAC подключения. Для
  Subscriber 360 MAC пока **UNKNOWN**.
- **UNKNOWN:** ни один столбец схемы не содержит `onu`, `olt`, `epon` или
  `gpon`; единственный столбец с `serial` относится к `accounts` и
  обозначает `irdeto_stb_serial_number`. `slink_tech_param` пуст. ONU ID
  нельзя извлекать из этого поля или придумывать.
- **UNKNOWN:** две живые модели `switch_types.name` содержат `BDCOM` и
  используются 25 живыми коммутаторами, но нет проверенного правила,
  позволяющего назвать их Ethernet, EPON или GPON; названия типов OLT/EPON/GPON
  не встречаются. В NetUP-карточке `access_type=UNKNOWN` до отдельного
  источника/правила сопоставления. BDCOM само по себе не равно EPON.

## Проекция в существующий `Connection`

| Поле | Источник-кандидат | Правило/ограничение |
|---|---|---|
| `ip_group` | `iptraffic_service_links.ip_group_id` | **VERIFIED** связь; строковое представление ID группы, если подтверждена его внешняя семантика. |
| `device` | `switches.name` по единственному ненулевому `ip_groups.switch_id` | JOIN и актуальность строки **VERIFIED**; использование имени как сетевого ID — **INFERRED**, нужна проверка владельца сети. |
| `port`, `vlan` | Единственные ненулевые `ip_groups.port_id/vlan_id` | Числовая непротиворечивость проверена. Физический формат порта и смысл VLAN — **INFERRED**. Несколько значений → `CONFLICT`, отсутствие → `UNKNOWN`. |
| `access_type` | Нет достоверного поля | `UNKNOWN` для Ethernet/EPON/GPON. |
| `onu_id` | Нет достоверного поля | `null`, `UNKNOWN`. |
| `address` | `users.actual_address` присутствует у многих пользователей | Это адрес пользователя, не доказанный адрес конкретного подключения. В `Connection.address` пока `null`; нужна модель адреса уровня абонента или подтверждение. |

Текущий `Connection` не имеет полей для отдельных IP/MAC. Расширение договора
API и источник этих значений обсуждаются отдельно. Ни одна из приведённых
колонок не является результатом live-диагностики оборудования.
